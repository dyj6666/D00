## 二、传感器控制（sensor 模块）
- 像素格式：RGB565 / GRAYSCALE
- 分辨率：**最高 QVGA(320x240)**（硬件上限，OpenMV 标准板的 VGA/5MP 不支持）
- 曝光/白平衡/增益：自动或手动（`set_auto_exposure` / `set_auto_whitebal` / `set_auto_gain`）
- 窗口裁剪 `set_windowing`、镜像/翻转 `set_hmirror` / `set_vflip`、特殊效果 `set_special_effect`
- 帧率：QVGA 彩色约 20-40fps（灰度更高；已实测显示正常）

## 四、能做 / 不能做（边界）

### ✅ 能实现（嵌入式视觉全明星）
- 色块追踪、线/矩形/圆检测、Apriltag/QR/条形码解码
- 模板匹配、特征点匹配、LBP 纹理
- 人脸/人眼 Haar 检测、光流、运动差分
- 数字/水果/动物等**小模型 CNN 分类**（tflite + nncu 双生态）
- 目标坐标提取（find_rects_center 模式）→ **串口输出给 MCU**（本项目规划）

### ❌ 受限 / 不能实现
| 限制 | 原因 |
| --- | --- |
| 高分辨率（>QVGA） | 摄像头硬件上限 QVGA |
| 通用目标检测（YOLO 等大模型） | 内存/算力限制；V4.3 固件不支持 YOLO（4.5+ 才部分支持，且仅小模型） |
| 通用 OCR（任意文字识别） | 无；数字识别需训练分类模型 |
| SLAM / 3D 重建 / 深度估计 | 单目无深度信息 |
| 视频流实时上传（>30fps 全帧） | USB 带宽 + 编解码开销 |
| 大模型 CNN / Transformer | 32MB SDRAM + 600MHz 上限 |
| 音频 | 无麦克风/音频接口 |

---

## 五、结论
OpenART mini 能覆盖**绝大部分经典嵌入式计算机视觉**（OpenMV 生态全部标准算法 + 逐飞 nncu/tflite AI 扩展），
对**智能车视觉组场景**（数字识别、赛道元素、目标坐标）完全够用；
但它是**单目小算力平台**——大模型、高分辨率、3D 类任务不在能力圈内。

## 六、下一步建议
1. 跑通本地最相关的例程：`find apriltag.py`、`find_rects_center.py`、`find number.py`（数字识别）
2. 基于 `find_rects_center.py` 设计"目标坐标 → UART 帧 → MCU"协议（项目主目标）
3. 需要新识别目标时用逐飞模型训练工具产出 nncu/tflite 模型
