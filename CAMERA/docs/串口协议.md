# 摄像头 ↔ MCU 串口通信协议（v0.1 草案）

> OpenART mini（UART2: TX=B12, RX=B13 @115200, 8N1）→ STM32F407
> 用途：体感交互游戏（手部坐标）、后续人脸/apriltag 坐标复用同帧结构
> 状态：协议先行，MCU 侧恢复后按此实现

## 帧格式

```
┌────────┬────────┬────────┬────────┬──────────────┬────────┐
│ 帧头   │ 类型   │ 长度   │ 数据   │ 校验         │        │
│ 0xAA 0x55 │ TYPE  │ LEN    │ DATA   │ SUM          │        │
│ 2B     │ 1B     │ 1B     │ LEN B  │ 1B           │        │
└────────┴────────┴────────┴────────┴──────────────┴────────┘
```

- **帧头**：`0xAA 0x55`（固定）
- **TYPE**：数据类型
  | TYPE | 含义 |
  |---|---|
  | 0x01 | 手部/目标坐标帧 |
  | 0x02 | 手势事件帧 |
  | 0x03 | 人脸坐标帧（预留） |
  | 0x04 | apriltag 帧（预留） |
  | 0xFE | 心跳/握手（预留） |
- **LEN**：DATA 字节数（0-255）
- **SUM**：从 TYPE 到 DATA 末尾所有字节的累加和（低 8 位）

## 0x01 手部坐标帧（LEN=9）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | flags | bit0：目标存在（1=有 0=无）；其余保留 0 |
| 1-2 | x (LE) | 目标中心 X，像素（QVGA 0~319） |
| 3-4 | y (LE) | 目标中心 Y，像素（QVGA 0~239） |
| 5-6 | w (LE) | 目标宽度（像素） |
| 7-8 | h (LE) | 目标高度（像素） |

发送频率：**30Hz**（每帧一包，115200 波特率下每包 ~1ms，余量充足）

## MCU 侧解析要点（供后续实现）

1. 串口 DMA/中断收字节 → 状态机：找帧头 → 收 TYPE/LEN → 收 DATA → 校验 SUM
2. 校验失败丢弃整帧（不清状态，等下一帧头）
3. 游戏坐标映射：x ∈ [0,319] → 屏幕横坐标（240 宽：`sx = x * 240 // 320`）
   y 可作为"远近"参考（手离镜头越近 y 越大/块越大）
4. 超时保护：500ms 无有效帧 → 目标丢失（游戏角色回到默认位置/暂停）
5. flags=0 帧同样要处理（显式"无目标"）

## 0x02 手势事件帧（LEN=1）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | gesture_id | 见下表 |

| gesture_id | 手势 | 说明 |
|---|---|---|
| 0x00 | NONE | 目标丢失/无事件（可选发） |
| 0x01 | SWIPE_LEFT | 快速向左挥 |
| 0x02 | SWIPE_RIGHT | 快速向右挥 |
| 0x03 | SWIPE_UP | 快速向上挥 |
| 0x04 | SWIPE_DOWN | 快速向下挥 |
| 0x05 | GRAB | 捏合/抓取（面积快速变化） |
| 0x06 | HOVER | 悬停（位置稳定 ≥0.8s，悬停期间每 500ms 重发） |

发送：**事件触发时发一帧**（非每帧）；HOVER 持续期每 500ms 重发一次。
MCU 侧：收到 0x02 立即执行对应动作；无事件时依赖 0x01 坐标帧的
存在标志与超时保护。

## 示例帧

手在 (160, 180)，尺寸 60x70：
```
AA 55 01 09 01 A0 00 B4 00 3C 00 46 00 → SUM
SUM = 0x01 ^ ... （按定义计算：0x01+0x09+0x01+0xA0+0x00+0xB4+0x00+0x3C+0x00+0x46+0x00 = 0x1D1 → 低8位 0xD1）
AA 55 01 09 01 A0 00 B4 00 3C 00 46 00 D1
```

## 验证方法（无 MCU 时）

OpenART 侧 `hand_track.py` 同时 `print` 可读文本（IDE 串口终端直接看），
UART 帧同步发出——协议正确性以 print 数据为准，MCU 恢复后按本协议解析即可。
