# D00 OTA 升级中心 · 使用与验证手册

> 适用于 v3.0+ 亮色分栏界面。所有"升级"验证会**真实刷写板子**（build 号递增，
> 每轮约 20-26s），A/B 回滚兜底，安全可逆。

## 一、启动与界面速览

```powershell
D:\Python\python.exe D:\GIT-SPACE\D00\HOST\OTA_Tool\main.py
```

界面分左右两栏：
- **左栏（配置+操作）**：模式选择 → 传输设置 → 固件与安全 → 开始/停止/批量
- **右栏（观察）**：仪表盘（阶段条/进度/统计）→ 升级日志 → 版本库/设备信息

### B. 三模式连接测试（不改板子，推荐先全做）
| 模式 | 操作 | 预期 |
| --- | --- | --- |
| TCP | IP `192.168.10.10` 端口 9020 → 测试连接 | `✅ TCP 在线 · OTA 状态 state=0`，右上角胶囊变绿 |
| UART | COM13 @ 921600 → 测试连接 | `✅ 串口在线 · 协议版本 1` |
| HTTP | 服务端口 8080、板端 IP、控制通道 COM9 → 测试连接 | HTTP 服务 URL + 控制通道回显均 ✅，**30 秒内浏览器打开 URL 看到在线提示页** |

### C. 完整升级（三模式各跑一轮）
通用步骤：切模式 → 测试连接 → 开始升级 → 确认弹窗 → 观察 → 等 ✅。

**观察点（升级中）**：
- 阶段条：空闲→擦除→下载→校验→提交→运行 依次点亮
- 统计卡：进度、速率（TCP ~170-220KB/s / UART ~31KB/s / HTTP 拉取 ~3s）、ETA、耗时
- 日志：构建包信息 → 传输进度 → END → BOOT 七阶段（UART 模式可见
  `备份 RUN→擦除 APP→解密写入→提交→完成重启`）→ 验证结果

**通过标准**：日志以 `✅ 升级流程完成` 结尾，板子重启后
浏览器打开 `http://192.168.10.10:8080/api/status` 看到 uptime 已归零、ver=192。

### D. 版本库
| 操作 | 预期 |
| --- | --- |
| 点"刷新" | 历史记录逐条列出（版本/构建号/备注/日期） |

### E. 批量升级（多台板子）
UART 模式下方填多个端口（如 `COM13,COM16`）→ 批量升级 → 每台独立线程，
日志带 `[端口]` 前缀，build 号串行预分配不冲突。

### F. 停止与异常路径
| 场景 | 预期 |
| --- | --- |
| 升级中点"停止" | 引擎协作停止，日志提示已停止 |
| 串口被占用时测试连接 | 红色错误日志，明确端口占用 |
| IP 不通时测试 TCP | `❌ TCP 连接失败...` |
| 版本低于当前 | BEGIN 被拒（status=4 降级拦截） |
| build 号重复/过低 | BOOT 防重放拒绝（上位机自动递增可避免） |

## 四、常见问题
- **浏览器打不开 HTTP 测试地址**：测试服务只保持 30 秒，先点"测试连接"再开浏览器。
- **升级后板子短暂失联**：END 后板子重启约 15s，属正常。
- **私钥不落盘**：每次启动需手动粘贴或设环境变量 OTA_PRIVKEY。
- **无串口时端口列表为空**：offscreen/无 USB 转串口环境属正常，不影响 TCP/HTTP 模式。
